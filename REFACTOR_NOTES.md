# Рефакторинг: общий слой данных и разбиение admin.py

## Что сделано

### 1. Весь SQL вынесен в `core/repositories/`
Раньше SQL был размазан по сервисам бота, двум хендлерам бота и всем веб-роутерам, а одни и те же
запросы (например, «id активных админов», «актуальный график сотрудника») повторялись в 2–4 местах.
Теперь каждый запрос живёт в одном месте, а бот и веб-админка пользуются одними функциями.

- `core/db.py` — пул MySQL (перенесён из `bot/database.py`; старый модуль оставлен как обёртка).
- `core/clock.py` — `now_naive()` вместо повторяющегося `now_local().replace(tzinfo=None)`.
- `core/repositories/_sql.py` — построитель `WHERE`, `IN (...)`, пагинация.
- Сервисы `bot/services/*` больше не содержат SQL — только бизнес-логику.
- Веб-роутеры больше не собирают SQL из параметров запроса — фильтры передаются в репозиторий.

### 2. `bot/handlers/admin.py` (1155 строк) разбит на пакет
`bot/handlers/admin/`: `common`, `reports`, `inline`, `employees`, `payroll`, `settings`, `shifts`.
Под-роутеры подключаются в том же порядке, в котором хендлеры шли в старом файле.
Публичные функции (`manage_employees`, `active_workers`, `open_settings_menu`, `latest_reports`)
импортируются как раньше: `from bot.handlers import admin; admin.manage_employees(...)`.

### 3. Удалён мёртвый код
- Хендлеры `AdminScheduleState` / `AdminRateState` и сами эти состояния: состояния нигде не выставлялись,
  хендлеры были недостижимы (график и ставка меняются через сценарий «Изменить информацию»).
- `F.text == "/settings"` и `F.text == "/last_reports"` в admin: их всегда перехватывали
  `Command(...)` из `handlers/commands.py`, который подключён раньше.
- Неиспользуемые импорты и функции в веб-роутерах, дубли `_parse_dt_local`, сборки Excel-ответа,
  подписи сотрудника, разбора списков id в настройках.
- Дубль уведомления об опоздании: остался один `notifications.notify_admins_about_late`.

### 4. Мелочи
- Добавлен `.gitignore` для `__pycache__`.

## Что поменялось в поведении (намеренно, мелочи)
- Веб: карточка и форма графика берут **последний** активный график (`ORDER BY id DESC`), как и бот.
  Раньше без сортировки — при нескольких активных графиках строка была случайной.
- Веб: при входе с паролем, лежащим в БД открытым текстом, хэш перезаписывается один раз, а не дважды.
- Бот: не-админ, написавший «Настройки», получает одно сообщение «нет доступа», а не два.
- Ошибки отправки уведомления об опоздании теперь пишутся в лог, а не глотаются молча.

## Как проверялось
Зависимости в среде рефакторинга не ставились, поэтому живой запуск не делался. Вместо него:
- старый и новый код прогонялись на фейковой БД со ~170 сценариями (сервисы бота, все веб-эндпоинты
  со всеми фильтрами и выгрузками, 81 сценарий админских хендлеров на заглушке aiogram);
  сравнивались журналы SQL, отправленные ботом сообщения и клавиатуры, состояния FSM, контексты
  шаблонов и содержимое Excel — совпадают, кроме перечисленного выше и параметризации ключей
  (`WHERE key=%s` вместо `WHERE key='...'`);
- статическая проверка, что каждое импортируемое имя существует.

**Перед выкаткой** стоит один раз запустить бота и админку на тестовой базе.

# (ранее) Безопасная реорганизация проекта

## Что изменено

### 1. Вынесена общая навигация
Создан модуль `bot/ui/navigation.py`, где теперь лежат:
- `main_menu_callback_data()`
- `back_to_main_menu()`
- `with_back_button()`

Это убрало дубли одной и той же кнопки возврата из нескольких хендлеров.

### 2. Упрощены клавиатуры
В `bot/keyboards/inline.py`:
- оставлена одна каноничная реализация кнопки возврата через общий модуль;
- `profile_menu()` приведён к пустой клавиатуре без фиктивной пустой строки.

### 3. Сведены к одному варианту служебные кнопки возврата
Раньше одинаковая inline-кнопка «Вернуться в главное меню» собиралась в нескольких местах разным кодом.
Теперь используется один общий генератор.

### 4. Удалены неиспользуемые сценарии редактирования профиля сотрудником
Из проекта убраны неиспользуемые callback-сценарии:
- `profile:full_name`
- `profile:phone`

Также удалён `ProfileState`, так как в текущем интерфейсе эти кнопки больше не выводятся.

### 5. Починены и унифицированы slash-команды
В `bot/handlers/commands.py` исправлены вызовы, чтобы они открывали те же экраны, что и меню:
- `/grafic` теперь вызывает экран графика с корректной сигнатурой
- `/settings` теперь открывает тот же экран настроек, что и кнопка в меню

### 6. Добавлены каноничные функции открытия админских экранов
В `bot/handlers/admin.py` добавлены/оформлены как отдельные точки входа:
- `manage_employees(...)`
- `active_workers(...)`
- `open_settings_menu(...)`

Это устраняет расхождение между кнопками меню и командами.

## Анализ дублей меню и кнопок

### Объединено
- Все варианты inline-кнопки возврата в главное меню → один общий генератор
- Открытие экрана настроек из кнопки и из slash-команды → один и тот же сценарий
- Открытие управления сотрудниками и списка активных сотрудников подготовлено как единые точки входа для повторного использования

### Оставлено как есть намеренно
- `menu:last_reports` и `menu:active_workers` callback-хендлеры оставлены для обратной совместимости, даже если в текущих клавиатурах основное открытие идёт через inline query
- Две формы запуска некоторых экранов (кнопка + slash-команда) оставлены, но приведены к единой логике, чтобы не ломать привычные сценарии

## Почему это безопасно
- внешние названия файлов основных модулей не ломались;
- существующие callback_data для рабочих кнопок сохранены;
- добавлена только общая обвязка, а не смена бизнес-логики;
- команды стали вызывать корректные функции вместо расходящихся реализаций.
